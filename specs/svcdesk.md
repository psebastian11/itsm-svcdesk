# svcdesk - System Specification (Lab 1)

## Overview
This document defines the functional and interface specification for the `svcdesk` service based on REQUIREMENTS.md and API.md. The service provides an HTTP JSON API for incident management, SLA tracking, and lifecycle transitions.

## Data Model
Each ticket possesses:
- `id`: Non-empty UUID generated by the server.
- `title`: String between 1 and 200 characters (mandatory).
- `description`: Optional string up to 4000 characters (default: "").
- `reporter`: Object containing `name` (1..100 characters, required), optional `email`, and optional `vip` (boolean, default: false).
- `impact`: Integer from {1, 2, 3}.
- `urgency`: Integer from {1, 2, 3}.
- `priority`: Derived automatically as P1, P2, P3, or P4. Under decision C3 (`vip`), tickets with `reporter.vip == true` will have their priority promoted to P2 if initially mapped to P3 or P4.
- `state`: Follows the explicit transition flow: `new` -> `acknowledged` -> `in_progress` -> `resolved` -> `closed`.
- `created_at`, `acknowledged_at`, `resolved_at`, `closed_at`: RFC 3339 timestamps in UTC with `Z` suffix.
- `sla`: Contains `ack_due_at` and `resolve_due_at` computed at creation time.

## SLA Clocks and Targets (C1)
- P1 tickets use continuous wall-clock time (`created_at + target`). Targets: Ack = 15 minutes, Resolve = 4 hours.
- P2, P3, P4 tickets use the Warsaw business-hours clock (Mon-Fri 08:00:00 to 16:00:00 Europe/Warsaw). Time outside business hours pauses target consumption.
  - P2: Ack = 1h, Resolve = 8h
  - P3: Ack = 4h, Resolve = 24h
  - P4: Ack = 8h, Resolve = 72h

## State Machine and Reopening (C2)
- Reopening is allowed strictly when `state == "resolved"` and current time `now <= resolved_at + 7 days`.
- Transitioning or reopening a ticket with `state == "closed"` returns HTTP 409 Conflict.
- Any invalid state transition returns HTTP 409 Conflict.

## Endpoints
- `GET /health`: Returns HTTP 200 with `{"status": "ok", "service": "svcdesk"}`.
- `POST /tickets`: Creates a new ticket, validates fields, computes priority and SLA deadlines. Returns HTTP 201.
- `GET /tickets`: Returns an array of tickets matching optional query parameters `state` and `priority`.
- `GET /tickets/{id}`: Returns the complete ticket object or 404 if not found.
- `GET /tickets/{id}/sla`: Returns priority, deadlines, and boolean flags `ack_breached`, `resolve_breached`, and `paused`.
- Action endpoints: `POST /tickets/{id}/ack`, `/start`, `/resolve`, `/close`, `/reopen` executing state transitions.
